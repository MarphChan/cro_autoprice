# 字段说明

本文档基于 [src/shared/schema.ts](file:///Volumes/SANDISK%20ELE/CRO-Sales/innostar_demo_1008/src/shared/schema.ts) 整理，对应的受版本管理示例见 [expertExample.json](expertExample.json)。本机演示记录同步放在 `data/records/expertExample.json`，该目录下的 JSON 不纳入版本管理。

## 使用说明

- `values` 中的键名必须使用字段 `id`
- `select` 填单个字符串，值应使用选项里的 `value`
- `multiselect` 填字符串数组，数组成员应使用选项里的 `value`
- `number` 在当前记录结构中也按字符串保存
- `required = 是` 表示创建供试品表时需确认的字段；未完成的草稿也可以保存
- `pending` 表示待确认，不视为已完成；交接信息不设阶段字段，也不做交接时的自动必填校验
- 疾病类型与毒理试验地点提供问卷选项，但仍允许填写更具体的自由文本
- `article.drugType` 保存子类编码数组，大类可通过 `getDrugTypeCategories` 从子类推导，不能按大类推测子类
- 旧记录只有单个大类时，读取时保留到 `legacyDrugType` 以供核对；具体子类保持空数组，保存后原分类仍会保留

### 药物类型子类编码对照

`values["article.drugType"]` 存储子类 `value` 的数组，例如 `["4-8", "7-1"]` 表示同时选择“生物制品-单抗”和“基因治疗-AAV载体”。括号内的大类标识由子类推导，不作为新的药物类型字段单独保存。不同大类下的“其他”编码互不通用；`5-1` 的 **TII** 保留原模板写法。

## 三、交接信息补充

| 字段ID | 字段名称 | 类型 | 必填 | 说明/可选值 |
| --- | --- | --- | --- | --- |
| `handover.projectStartDate` | 项目启动日期 | `date` | 否 | 建议格式：`YYYY-MM-DD` |
| `handover.useTechnologyVouchers` | 是否使用科技券 | `select` | 否 | `yes`=是；`no`=否；`pending`=待确认 |
| `handover.toxicologyLocation` | 毒理试验开展地点 | `text` | 否 | 建议项：上海、南通、深圳；也可填写具体中心名称 |
| `handover.statutoryReportingDate` | 法定报告日期 | `date` | 否 | 建议格式：`YYYY-MM-DD` |
| `handover.translationReportDate` | 翻译报告日期 | `date` | 否 | 建议格式：`YYYY-MM-DD` |
| `handover.sendDate` | SEND 日期 | `date` | 否 | 建议格式：`YYYY-MM-DD` |
| `handover.deliveryDate` | 供试品送达日期 | `date` | 否 | 建议格式：`YYYY-MM-DD` |

第三部分创建时非必填；项目交接时按原问卷补齐。科技券选填，翻译报告日期在有翻译时填写。本系统不保存创建/交接阶段，也不按阶段阻止保存。
